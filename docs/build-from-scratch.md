# Сборка RGB-табло ANENJI 64×32 с нуля

> **Статус:** инструкция основана на актуальных исходниках проекта. Электрические подключения, особенно фиксированные RGB-пины библиотеки, необходимо сверить с маркировкой конкретной HUB75-панели и версией RGBmatrixPanel. Схема не заменяет проверку мультиметром. Прошивки не подтверждены аппаратным тестом.

## 1. Что строим

```text
        Локальная сеть Wi-Fi
   RMS / OpenWrt /api/rgb (HTTP)
                  |
               Wi-Fi
                  |
          +---------------+
          | ESP8266 3.3 V |  HTTP -> компактный UART DATA
          +---------------+
            TX       RX
             |        ^
             v        |  через преобразователь 5V -> 3.3V
          RX3(15)   TX3(14)
          +-------------------+
          | Arduino Mega 2560|
          | Serial3 19200 8N1|
          +-------------------+
           | HUB75   | D8
           v         v
       RGB 64x32   активный буззер
           ^
           |
       5 V мощный БП
```

Mega рисует экраны ENERGY/CLOCK/AUTONOMY, ESP8266 опрашивает сервер. Компьютер нужен только для прошивки и диагностики.

## 2. Список компонентов

| Компонент | Требование |
|---|---|
| RGB LED матрица | HUB75, 64×32, совместимая с `RGBmatrixPanel` и выбранным сканированием (проверить 1/16 scan) |
| Контроллер | Arduino Mega 2560, ATmega2560 |
| Wi-Fi мост | ESP8266 DevKit / NodeMCU (или другой модуль с корректным питанием 3.3 В) |
| Питание панели | **Стабилизированный 5 В БП** с током по спецификации именно вашей матрицы; ориентир для одной 64×32 панели — несколько ампер, закладывайте запас |
| Питание ESP8266 | Надёжные 3.3 В, достаточный ток для пиков Wi-Fi (обычно нужен запас не менее 500 мА); у NodeMCU можно использовать предусмотренный вход питания согласно его плате |
| Кабель HUB75 | 16-контактный IDC-шлейф с правильной ориентацией |
| Провод питания | Подходящее сечение, надёжные клеммы, предохранитель по току цепи |
| UART level shifter | 5 В -> 3.3 В для Mega TX3 -> ESP RX (или правильно рассчитанный резистивный делитель) |
| Буззер (опционально) | Активный малотоковый 5 В, либо транзисторный ключ для большей нагрузки |
| Дополнительно | Корпус, стойки, изоляция, USB-кабели, мультиметр |

**Не подавайте 5 В на вывод 3.3 В ESP8266.** Не запитывайте RGB-матрицу от вывода 5V Mega, USB компьютера или тонкого сигнального провода. Силовые провода подключаются напрямую к БП. Не подключайте сетевую часть 230 В без соответствующей квалификации; безопаснее готовый сертифицированный блок питания.

## 3. HUB75: подключение Mega -> панель

Актуальная Mega-прошивка содержит:

```cpp
#define CLK 11
#define OE   9
#define LAT  10
#define A    A0
#define B    A1
#define C    A2
#define D    A3
RGBmatrixPanel matrix(A, B, C, D, CLK, LAT, OE, false, 64);
```

| HUB75 вход | Mega 2560 | Назначение |
|---|---|---|
| R1 | D24* | красный, верхняя половина |
| G1 | D25* | зелёный, верхняя половина |
| B1 | D26* | синий, верхняя половина |
| R2 | D27* | красный, нижняя половина |
| G2 | D28* | зелёный, нижняя половина |
| B2 | D29* | синий, нижняя половина |
| A | A0 | адрес строки |
| B | A1 | адрес строки |
| C | A2 | адрес строки |
| D | A3 | адрес строки |
| CLK | D11 | тактирование |
| LAT / STB | D10 | защёлка |
| OE | D9 | разрешение выхода (часто активный низкий) |
| GND | общий GND | сигнальная земля |
| E | **не используется в этой конфигурации** | не подключать без изменения кода и проверки сканирования |

**\* Важное ограничение:** выводы RGB D24–D29 характерны для реализации Adafruit RGBmatrixPanel на Mega 2560, где RGB-линии аппаратно фиксированы библиотекой и не задаются в конструкторе. Перед монтажом сверяйте `RGBmatrixPanel.cpp/.h` установленной версии: при другом форке/версии соответствие может отличаться.

Панель подключать к разъёму **INPUT / IN**, а не OUTPUT / OUT. Маркировка и ориентация ключа у производителей различаются. **Не полагайтесь на положение красной полосы IDC-шлейфа без проверки pin 1 и маркировки платы.** Контакты питания панели (обычно отдельный 4-контактный силовой разъём) не заменяются сигнальным HUB75.

### Текстовая электрическая схема

```text
MEGA D24..D29 --------------------> HUB75 R1 G1 B1 R2 G2 B2
MEGA A0,A1,A2,A3 -----------------> HUB75 A B C D
MEGA D11 ------------------------> HUB75 CLK
MEGA D10 ------------------------> HUB75 LAT
MEGA D9 -------------------------> HUB75 OE
MEGA GND ------------------------> HUB75 GND

БП +5V -- предохранитель --------> ПАНЕЛЬ +5V (силовой вход)
БП GND --------------------------> ПАНЕЛЬ GND (силовой вход)
БП GND --------------------------> MEGA GND (общая земля)
```

Панель и Mega должны иметь общую сигнальную землю. Mega можно питать отдельно через USB или предусмотренный вход питания, соблюдая требования платы; **не соединяйте бездумно выходы двух разных источников +5 В**.

## 4. ESP8266 ↔ Mega (Serial3)

| Mega 2560 | ESP8266 | Условие |
|---|---|---|
| D14 / TX3 (5 В) | RX / GPIO3 | **только через преобразование уровня 5 -> 3.3 В** |
| D15 / RX3 | TX / GPIO1 (3.3 В) | прямое соединение обычно допустимо для ATmega2560 при питании 5 В, но проверьте электрические уровни вашей платы |
| GND | GND | обязательная общая земля |
| — | 3.3 V / питание DevKit | по требованиям конкретной ESP-платы |

```text
Mega TX3 D14 ----[level shifter 5->3.3]----> ESP RX
Mega RX3 D15 <----------------------------- ESP TX
Mega GND ---------------------------------- ESP GND
```

**Внимание:** GPIO1/GPIO3 ESP8266 также используются для USB-UART программирования и загрузочных сообщений. На время прошивки ESP при необходимости отключите провода RX/TX к Mega. Для «голого» ESP-01 требуется отдельная схема EN/CH_PD, GPIO0, RESET и питание 3.3 В; NodeMCU проще для начинающих.

Скорость прошивок: **19200 8N1**. Диагностический USB Serial у Mega — **115200 бод**.

## 5. Буззер

Актуальный исходник задаёт `BUZZER_PIN 8`, предполагается **активный** буззер, активный высокий уровень. Для малотокового буззера: D8 -> «+» буззера, «−» -> GND, **только если потребляемый ток безопасен для GPIO**. Для более мощного буззера используйте транзисторный ключ, резистор в базе/затворе и соответствующую защиту. При `attention_required=1` прошивка подаёт короткий сигнал примерно раз в 5 секунд.

## 6. Подготовка ПО

1. Установите Arduino IDE 2.x или `arduino-cli`.
2. Для Mega выберите **Arduino Mega or Mega 2560**, процессор **ATmega2560**, правильный порт.
3. Для ESP8266 установите поддержку плат ESP8266; выберите **точную модель** DevKit/NodeMCU.
4. Для Mega требуются `RGBmatrixPanel` (Adafruit), `Adafruit GFX Library` и `U8g2_for_Adafruit_GFX` (плюс их зависимости). Устанавливайте совместимые версии через менеджер библиотек.
5. Исходники проекта:
   - Mega: [firmware/mega/anenji_rgb_display.ino](../firmware/mega/anenji_rgb_display.ino)
   - ESP: [firmware/esp8266/anenji_esp8266_bridge_stage1_grid_present.ino](../firmware/esp8266/anenji_esp8266_bridge_stage1_grid_present.ino)

Arduino IDE обычно требует, чтобы основной `.ino` лежал в каталоге с таким же именем, как сам файл. Скопируйте каждый скетч в собственную одноимённую папку или используйте скрипт сборки из GitHub Actions, если он доступен.

arduino-cli core update-index

## 7. Первоначальная прошивка ESP8266 и переключатели

### Какой модуль используется

В проекте прошивка рассчитана на **ESP8266**. На NodeMCU / WeMos D1 mini обычно есть USB-UART и кнопки **FLASH/BOOT** и **RST/RESET**; у ESP-01, ESP-12 на переходной плате и модулей с DIP-переключателями схема входа в загрузчик и питание отличаются. **В репозитории нет модели платы-переходника и таблицы её переключателей**: положения «SW1 ON, SW2 OFF» без маркировки конкретной платы давать опасно. Если на вашей плате есть DIP-переключатели, сначала определите, какие из них соединяют GPIO0, EN/CH_PD, RESET и UART с USB-программатором; не переключайте их наугад под питанием.

### Визуальная идентификация платы перед прошивкой

**Сначала определите, что у вас за плата:** от этого зависят и USB-порт, и положения переключателей. Не существует универсальной таблицы DIP для всех плат с ESP8266.

| Что написано на плате | Как обычно прошивать | Что делать с переключателями |
|---|---|---|
| **Arduino Mega 2560 R3** без Wi-Fi | USB-порт самой Mega, файл `anenji-mega2560.hex` | Обычно никаких DIP для выбора порта нет |
| **NodeMCU ESP8266 / ESP-12E** | USB на NodeMCU, файл `anenji-esp8266.bin` | Обычно автоматический вход в загрузчик; при необходимости FLASH + RESET |
| **WeMos / LOLIN D1 mini ESP8266** | USB на D1 mini, тот же `.bin` | Обычно автоматический вход в загрузчик |
| **Mega 2560 + WiFi R3 / ATmega2560+ESP8266**, одна комбинированная плата | Один USB-UART может переключаться между Mega и ESP | **Нужна таблица именно вашей ревизии**: DIP часто выбирает USB↔Mega, USB↔ESP, Mega↔ESP и GPIO0/FLASH |
| **ESP-01 / ESP-12 с отдельным USB-UART** | USB-UART 3.3 В, тот же `.bin` | GPIO0 LOW при RESET для прошивки, затем HIGH для RUN; проверить обвязку |

**Фото и ориентиры для сравнения внешнего вида:**
- [Arduino Mega 2560 — официальная страница с изображениями платы](https://docs.arduino.cc/hardware/mega-2560/)
- [ESP8266 DevKitC — документация Espressif и изображения разъёмов](https://docs.espressif.com/projects/esp-dev-kits/en/latest/esp8266/esp8266-devkitc/user_guide.html)
- [NodeMCU — примеры внешнего вида разных ревизий](https://commons.wikimedia.org/wiki/Category:NodeMCU)
- [HUB75 RGB LED matrix — примеры плат и шлейфов](https://learn.adafruit.com/32x16-32x32-rgb-led-matrix/connecting-using-a-hub75-rgb-matrix-adapter)

Это **справочные изображения**, а не фото именно вашей платы. Если у вас комбинированная Mega+WiFi с DIP, приложите **чёткое фото лицевой стороны, блока переключателей и маркировки ревизии**: тогда можно добавить в инструкцию проверенную таблицу `ON/OFF` для USB→ESP (FLASH), USB→Mega и Mega↔ESP (RUN), без риска ошибиться.

### Порядок для комбинированной Mega 2560 + WiFi R3 с DIP

1. **При выключенном питании** прочитайте точное обозначение платы, ревизию и подписи возле DIP (например, `USB`, `ESP`, `MCU`, `RX`, `TX`, `GPIO0`). Запишите исходные положения или сделайте фото.
2. Найдите схему **именно этой ревизии**. По ней определите три отдельные конфигурации: **USB↔ATmega2560** (запись HEX), **USB↔ESP8266 + GPIO0 LOW** (запись BIN), **ATmega2560↔ESP8266 + GPIO0 HIGH** (рабочий обмен). Это три логических маршрута, **не номера DIP**.
3. Выключите питание, поставьте переключатели в режим **USB↔Mega**, подключите USB и прошейте Mega файлом `anenji-mega2560.hex` через avrdude.
4. Выключите питание, поставьте DIP в режим **USB↔ESP (FLASH)** по документации платы; если нужен ручной сброс, удерживайте GPIO0/FLASH в LOW при RESET. Подключите USB и запишите `anenji-esp8266.bin` по адресу `0x00000`.
5. Выключите питание. Верните **GPIO0 в HIGH (RUN)** и выставьте по документации маршрут **Mega↔ESP** для UART-обмена; при необходимости отключите USB-UART от линий ESP. Перезапустите плату.
6. Проверьте, что Mega и ESP обмениваются `REQCFG`/`CFG` на 19200 бод. **Не переключайте DIP под напряжением**.

> **Важно для комбинированных плат:** выводы Mega `TX3 D14 / RX3 D15`, используемые текущей прошивкой, могут **не совпадать** с аппаратно разведённым маршрутом Mega↔ESP через DIP. На некоторых платах этот маршрут подключён к другому UART Mega. Если на схеме нет связи именно с Serial3, потребуется отдельная проводка к D14/D15 с согласованием уровней либо изменение прошивки. Простое переключение DIP не гарантирует совместимость.

### Как понять, какой COM-порт выбран

- **Windows:** откройте «Диспетчер устройств → Порты (COM и LPT)» до и после подключения USB; появившийся `COMx` используйте в esptool/avrdude.
- **Linux:** перед подключением и после него сравните `ls /dev/ttyUSB* /dev/ttyACM* 2>/dev/null`; дополнительно можно посмотреть `dmesg | tail -n 30` (при наличии прав).
- **Один USB-порт на комбинированной плате** не означает одновременный доступ к Mega и ESP: переключатели перенаправляют линии RX/TX. Закройте Serial Monitor перед прошивкой.

### Режимы загрузки ESP8266

| Сигнал | Прошивка через UART (download mode) | Обычный запуск |
|---|---|---|
| GPIO0 | **LOW (GND) в момент сброса** | **HIGH / подтяжка к 3.3 В** |
| GPIO2 | HIGH / подтяжка к 3.3 В | HIGH / подтяжка к 3.3 В |
| GPIO15 | LOW / GND | LOW / GND |
| EN / CH_PD | HIGH / 3.3 В | HIGH / 3.3 В |
| RESET / RST | кратковременно LOW для перезапуска | кратковременно LOW для перезапуска |

Это **логические уровни ESP8266**, а не универсальная нумерация DIP-переключателей. На NodeMCU/WeMos GPIO2/GPIO15 и EN обычно уже обвязаны на плате; кнопка FLASH/BOOT обычно удерживает GPIO0 в LOW. На ESP-01 GPIO15 обычно не выведен на гребёнку и обвязка зависит от модуля/адаптера. **Все GPIO ESP8266 — 3.3 В; не подавайте на них 5 В.**

### Прошивка готового образа `.bin` — с нуля

1. Отключите питание табло и **отсоедините ESP TX/RX от Mega**. Подключите ESP к компьютеру по USB (NodeMCU/WeMos) или через **USB–UART адаптер 3.3 В** с правильным питанием для отдельного модуля. Общая земля обязательна.
2. Скачайте **`anenji-esp8266.bin`** из [последнего GitHub Release](https://github.com/DanilVDV/anenji-rgb-display/releases/latest). Не путайте его с исходником `.ino` или архивом исходного кода.
3. Установите [esptool](https://docs.espressif.com/projects/esptool/en/latest/esp8266/) на компьютер: `python -m pip install esptool`.
4. Переведите ESP в загрузчик: на NodeMCU/WeMos **удерживайте FLASH/BOOT, кратко нажмите RESET, затем отпустите FLASH/BOOT**. На плате без кнопок выставьте GPIO0=LOW и сделайте сброс; на адаптере с DIP установите эквивалентные сигналы **по его собственной схеме**. Некоторые USB-платы входят в режим прошивки автоматически.
5. Определите порт: в Linux обычно `/dev/ttyUSB0` или `/dev/ttyACM0`, в Windows — `COM3` и т. п. Закройте Serial Monitor и другие программы, использующие этот порт.
6. Выполните команду, заменив порт и путь к файлу:

   ```bash
   python -m esptool --chip esp8266 --port /dev/ttyUSB0 --baud 115200 write_flash 0x00000 anenji-esp8266.bin
   ```

   Адрес **`0x00000` относится к обычному Arduino ESP8266 sketch `.bin`**, который создаёт текущий GitHub Actions, а не к произвольному полному дампу флеш-памяти. **Не применяйте этот адрес к другим образам без их документации.** Если ваша версия esptool использует иной синтаксис, смотрите `python -m esptool --help`. При нестабильной записи снизьте скорость до 57600.
7. После сообщения об успешной записи **верните GPIO0 в HIGH / нормальный режим**, перезапустите ESP кнопкой RESET или переподайте питание. У NodeMCU/WeMos достаточно отпустить FLASH/BOOT и нажать RESET. На DIP-плате **верните переключатель BOOT/FLASH в режим RUN** согласно схеме адаптера.
8. **Только после отключения питания** восстановите соединения ESP TX/RX ↔ Mega и общую землю; питание включайте после проверки уровней.

**Важно:** `erase_flash` не требуется для обычного обновления. Полное стирание уничтожит сохранённую ESP конфигурацию в эмулируемой EEPROM; применяйте его только осознанно. При первой прошивке пустой ESP прошивка сама запросит настройки у Mega по UART.

### Если прошиваете из Arduino IDE, а не готовый BIN

Откройте [ESP-скетч](../firmware/esp8266/anenji_esp8266_bridge_stage1_grid_present.ino), установите пакет плат ESP8266, выберите **фактическую модель** (например, NodeMCU 1.0 или Generic ESP8266 Module), порт и нажмите **Upload**. Для платы с ручным BOOT-переключателем действуют те же правила GPIO0/RESET. Arduino IDE сама компилирует скетч и передаёт его загрузчику. Готовый релизный BIN удобнее, если изменять исходный код не требуется.

### Первый запуск и диагностика

После запуска ESP посылает в Mega сообщение **`REQCFG`** по UART **19200 8N1**. Mega отвечает строкой `CFG|...`; ESP сохраняет конфигурацию в EEPROM, подключается к Wi-Fi и опрашивает RMS. Это **не веб-мастер первоначальной настройки и не отдельный «заводской образ»**: текущая прошивка — самостоятельный UART/Wi-Fi мост. Для её работы Mega должна быть прошита совместимой версией и иметь корректные настройки сети.

USB Serial Monitor на ESP при подключённом Mega может перехватывать тот же UART и мешать обмену. Если не удаётся прошить, проверьте питание, порт, USB-кабель с линиями данных, отключение UART Mega и состояние GPIO0 при сбросе. Если запись проходит, но ESP не запускается, сначала проверьте возврат в RUN и корректность выбранного типа платы/флеш-памяти.

### Прошивка Mega готовым файлом `.hex`

Скачайте `anenji-mega2560.hex` из того же Release, подключите Mega по USB и используйте **avrdude** с загрузчиком Arduino Mega 2560 (порт подставьте свой):

```bash
avrdude -p atmega2560 -c wiring -P /dev/ttyACM0 -b 115200 -D -U flash:w:anenji-mega2560.hex:i
```

Эта команда предполагает штатный USB-загрузчик Mega 2560. При другом загрузчике или клоне параметры могут отличаться. Для прошивки через Arduino IDE можно вместо HEX открыть исходный Mega-скетч и нажать Upload.

## 8. Wi-Fi и сервер

В Mega исходнике есть локальные параметры:

```cpp
const char RMS_WIFI_SSID[] = "ap";
const char RMS_WIFI_PASS[] = "<WIFI_PASSWORD>";
const char RMS_HOST[] = "192.168.54.30";
const uint16_t RMS_HTTP_PORT = 8088;
const char RMS_RGB_PATH[] = "/api/rgb";
```

Перед сборкой укажите свои SSID, пароль и IP/имя сервера **только в локальной копии**. Пароль нельзя публиковать в GitHub или логах. Учтите, что текущая реализация отправляет конфигурацию с паролем по UART, а ESP хранит её в EEPROM без шифрования; используйте доверенное устройство и сеть.

На RMS должен быть доступен компактный HTTP endpoint `http://<HOST>:8088/api/rgb`. Убедитесь, что ESP находится в сети с доступом к серверу. Поля и CRC UART описаны в [protocol.md](protocol.md). Расширенные поля настроек поддерживаются Mega, но **не гарантированы сервером и ESP**.

## 9. Первый запуск по шагам

1. **Без питания** проверьте мультиметром отсутствие короткого замыкания между +5V и GND панели; проверьте полярность силового разъёма и все земли.
2. Проверьте напряжение 5 В БП **без панели**, затем под нагрузкой; оно должно оставаться в пределах требований производителя.
3. Подключите и прошейте Mega по USB, открыв Serial Monitor на 115200 бод.
4. Отдельно прошейте ESP8266; убедитесь, что он запускается, и только затем подключите UART через преобразователь уровней.
5. Сначала подключите HUB75 сигналы и общую землю **при выключенном питании**, затем силовое питание панели.
6. Подайте питание. Если экран пуст, проверьте **INPUT**, ориентацию IDC, GND, сканирование панели и соответствие пинов RGB установленной библиотеке.
7. Проверьте доступность `/api/rgb`, обмен `REQCFG` / `CFG` / `DATA` и обновление SOC.
8. Проверьте переход ENERGY/CLOCK, экран AUTONOMY при разряде и звуковую индикацию. Не тестируйте разряд аккумулятора рискованными экспериментами с силовой системой.

## 10. Типовые неисправности

| Симптом | Что проверить |
|---|---|
| Экран полностью чёрный | +5V/GND панели, ток БП, вход INPUT, OE/LAT/CLK, исправность Mega |
| Неправильные цвета | порядок R/G/B, фиксированные Mega RGB-пины, соответствие версии библиотеки |
| Полосы, половина изображения, сдвиг строк | тип сканирования панели, линии A–D, наличие/необходимость E, совместимость 64×32 |
| Мерцание или перезагрузка | просадка питания, силовые провода, общая земля, неправильная конфигурация библиотеки |
| Нет телеметрии | ESP Wi-Fi, IP/порт/путь RMS, UART TX/RX, 19200 бод, CRC |
| ESP не прошивается | отключить соединение UART с Mega, проверить загрузочный режим и USB-кабель |
| Появляется `<WIFI_PASSWORD>` | это заглушка: нужно указать локальный пароль перед сборкой |
| Буззер не звучит | D8, полярность, активный тип, наличие `attention_required` |

## 11. Безопасность и ограничения

- HUB75 — не универсальный стандарт электрической совместимости: **сверьте маркировку входа и pinout своей панели**.
- Панель может потреблять значительный ток. Используйте предохранитель, качественные провода и охлаждение.
- **Не подавайте 5 В на входы ESP8266** и не подключайте к ней сетевое напряжение.
- RGBmatrixPanel для Mega имеет ограничения по поддерживаемым панелям и RAM. 64×32/1:16 следует проверить именно с вашим модулем.
- Это проект на базе пользовательских прошивок. **Сборка, прошивка и аппаратная проверка не заменяются наличием инструкции.**
